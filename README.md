# Xray Binary Mirror

Репозиторий автоматически публикует распакованный Linux x86-64 бинарный файл из официальных релизов [XTLS/Xray-core](https://github.com/XTLS/Xray-core).

## Назначение

Официальный проект распространяет Linux-сборку в архиве `Xray-linux-64.zip`. Некоторые системы обновления, включая загрузчики пользовательского ядра, ожидают прямую ссылку на исполняемый файл и не умеют распаковывать ZIP.

Этот репозиторий предоставляет такой файл без пересборки и модификации.

## Как работает автоматизация

GitHub Actions один раз в сутки, а также при ручном запуске:

1. запрашивает опубликованные releases и pre-releases из `XTLS/Xray-core`;
2. выбирает только `Xray-linux-64.zip` и официальный `Xray-linux-64.zip.dgst`;
3. проверяет размеры и SHA-256 обоих загруженных assets по данным GitHub API;
4. проверяет SHA-256 архива по официальному `.dgst`;
5. извлекает только файл `xray`;
6. переименовывает бинарник в `Xray-linux-64` (версия остаётся в теге release);
7. создаёт release с тем же тегом;
8. сохраняет статус источника: обычный release остаётся release, pre-release остаётся pre-release;
9. после публикации повторно читает release через API и проверяет его статус, имя asset и SHA-256.

Диапазон синхронизации закреплён в `mirror-state.json`: публикуются все официальные версии начиная с указанной там даты. Поэтому при пустом репозитории, а также после удаления всех публикаций, весь заданный диапазон восстанавливается за один запуск. Если upstream заменит assets под существующим тегом или переведёт pre-release в обычный release, зеркальная публикация будет пересоздана. Если upstream удалит релиз либо обязательные assets, соответствующая публикация зеркала переводится в draft.

## Содержимое публикаций

Каждая публикация содержит только один asset — исполняемый файл с постоянным именем:

```text
Xray-linux-64
```

Пример прямой ссылки:

```text
https://github.com/PentiumB/xray-binary/releases/download/v26.10.10/Xray-linux-64
```

## Гарантии происхождения

- исходный архив скачивается только из официального `XTLS/Xray-core`;
- идентификаторы и SHA-256 upstream assets сохраняются в служебных метаданных release;
- SHA-256 проверяется по официальному `.dgst`;
- бинарник не собирается заново и не изменяется;
- остальные файлы архива (`geoip.dat`, `geosite.dat` и другие) не публикуются.

Репозиторий не является официальным проектом XTLS и предназначен только для автоматической распаковки и публикации оригинального бинарника.
